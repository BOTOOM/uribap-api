# Data Model: Identity and Households

**Feature**: `002-identity-households`

## Entity: `app_user`

- `id`: UUID primary key generated by Uribap.
- `email`: nullable normalized email snapshot; never the identity key.
- `email_verified`: boolean snapshot from the provider.
- `display_name`: nullable safe display name.
- `status`: `active` or `disabled`.
- `created_at`, `updated_at`, `last_seen_at`: timezone-aware timestamps.
- `version`: integer optimistic-concurrency version.

Constraints:

- A disabled user cannot access household resources.
- Email is normalized for matching but may be changed by a later verified provider claim; it is a non-unique profile snapshot and never an identity key.
- No password, client secret, access token, refresh token, or invitation token is stored.

## Entity: `user_identity`

- `id`: UUID primary key.
- `user_id`: foreign key to `app_user`, not nullable.
- `issuer`: normalized OIDC issuer URL, not nullable.
- `subject`: OIDC `sub`, not nullable.
- `provider`: provider label, initially `zitadel`.
- `last_claims_at`, `created_at`, `updated_at`: timestamps.

Constraints:

- Unique `(issuer, subject)`.
- Index `(user_id)` and `(issuer, subject)`.
- Identity linking is idempotent and must not silently reassign an existing identity.

## Entity: `household`

- `id`: UUID primary key.
- `name`: trimmed human-readable name, 1–120 characters.
- `locale`: BCP 47-like locale string, default `es`.
- `timezone`: IANA timezone string, default configured local timezone.
- `status`: `active` or `archived`.
- `version`: integer optimistic-concurrency version.
- `created_at`, `updated_at`: timestamps.

Constraints:

- Name cannot contain control characters.
- Archived households cannot accept new mutations except documented restore/admin operations.
- An active household must retain at least one active owner.

## Entity: `household_member`

- `id`: UUID primary key.
- `household_id`: foreign key to `household`, not nullable.
- `user_id`: foreign key to `app_user`, not nullable.
- `role`: `owner`, `admin`, or `member`.
- `status`: `active`, `revoked`, or `left`.
- `joined_at`, `revoked_at`, `created_at`, `updated_at`: timestamps.
- `version`: integer optimistic-concurrency version.

Constraints:

- Unique active membership per `(household_id, user_id)`; historical revoked rows remain auditable.
- Index `(household_id, status, role)` and `(user_id, status)`.
- An owner may not demote or revoke the last active owner.
- Authorization always checks this table, not client-provided role claims.

## Entity: `household_invitation`

- `id`: UUID primary key.
- `household_id`: foreign key to `household`, not nullable.
- `invited_email`: normalized email, not nullable.
- `token_hash`: cryptographic hash, unique, not nullable.
- `requested_role`: `admin` or `member`; invitations cannot directly grant owner.
- `status`: `pending`, `accepted`, `revoked`, or `expired`.
- `expires_at`: timestamp, not nullable.
- `invited_by_user_id`: foreign key to `app_user`, not nullable.
- `accepted_by_user_id`: nullable foreign key to `app_user`.
- `accepted_at`, `revoked_at`, `created_at`, `updated_at`: timestamps.
- `version`: integer optimistic-concurrency version.

Constraints:

- Token hash is never returned.
- Accept requires pending status, current time before expiry, matching verified email, and an active user.
- Acceptance atomically changes status and creates or reactivates the membership.
- A household may have at most one equivalent pending invitation per normalized email/role unless explicitly resent.

## Entity: `audit_event`

- `id`: UUID primary key.
- `actor_user_id`: nullable user foreign key for system/provider events.
- `household_id`: nullable household foreign key.
- `action`: stable action code.
- `target_type`, `target_id`: nullable target reference.
- `request_id`: correlation ID.
- `metadata`: redacted JSON object without authorization headers, tokens, secrets, or raw invitation values.
- `created_at`: timestamp.

Properties:

- Append-only from application code.
- Covers identity provision/link, household create/update, membership role/revoke, invitation create/revoke/accept, and rejected authorization mutations where policy requires.

## Entity: `email_outbox_entry`

- `id`: UUID primary key.
- `dedupe_key`: unique idempotency key.
- `kind`: `verification`, `password_reset`, or `household_invitation`.
- `recipient_email`: normalized synthetic/local or production-recipient address.
- `template_data`: redacted JSON payload; raw invitation token is allowed only in the transient send payload and not persisted.
- `status`: `pending`, `sent`, or `failed`.
- `attempts`: non-negative integer.
- `available_at`, `sent_at`, `last_error`, `created_at`, `updated_at`: timestamps.

Properties:

- The first feature may dispatch synchronously through the SMTP adapter after transaction commit, but the outbox record remains the audit/retry boundary.
- Errors are redacted and do not include SMTP credentials or message bodies containing secrets.

## Relationships

```text
app_user 1──N user_identity
app_user 1──N household_member N──1 household
household 1──N household_invitation
app_user 1──N household_invitation (invited_by)
household_invitation N──0..1 app_user (accepted_by)
app_user 1──N audit_event
household 1──N audit_event
```

## State transitions

### Membership

```text
active(owner|admin|member) → active(new role)
active → revoked
active → left
```

The last active owner transition is rejected.

### Invitation

```text
pending → accepted
pending → revoked
pending → expired
```

Only `pending` invitations before `expires_at` may transition to `accepted`; the transition and membership creation are one database transaction.

## Index and isolation requirements

- Every household-owned query begins with an authorized `household_id` derived from membership.
- All foreign keys are indexed where PostgreSQL does not create a usable index automatically.
- Integration tests must run two households and two users and prove no cross-tenant row is returned or mutated.
- Concurrency tests use PostgreSQL transactions, not only in-memory mocks.
